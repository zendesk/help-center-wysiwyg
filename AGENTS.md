# Help Center WYSIWYG

A custom CKEditor 5 build packaged as a UMD library for Zendesk Help Center. Published to npm as `@zendesk/help-center-wysiwyg`, it provides rich-text editing for comments, community posts, and support request forms.

## Setup & Commands

```bash
# Install dependencies
yarn install --immutable

# Start dev server (example page at http://localhost:8080/)
yarn start

# Production build (outputs to dist/main.js)
yarn build

# Lint (ESLint + Prettier, zero warnings tolerated)
yarn lint

# Generate a changeset for your changes (required before merging)
yarn changeset
```

Node version is specified in `.nvmrc`. Use `nvm use` or the equivalent before starting.

## Code Conventions

- ES module syntax (`import`/`export`) throughout — no CommonJS `require()`
- CKEditor plugins are plain functions (not classes) unless they require CKEditor's Plugin API
- Plugin config objects are attached as `.config` property on the plugin function (see `CommunityMentionsPlugin.config`)
- Use `translate as t` from `../localization` (or `../../localization`) for all user-visible strings — never hardcode UI text
- `src/styles.css` **must be imported last** in `src/index.js` to override CKEditor's default styles
- Translations are managed via `translations.yml` (Zendesk localization system) — do not edit `translations/*.json` directly; they are auto-generated

## Editor Types

Three configurations are supported in `getEditorConfig()` in `src/index.js`:

| Editor Type | Use Case | Image Upload | Notable Plugins |
|------------|----------|--------------|-----------------|
| `comments` | Help Center comments | `AUSImageUploadPlugin` | `HiddenFormFieldsPlugin` (`content_type: text/html`), inline-only image style |
| `communityPosts` | Community posts | `AUSImageUploadPlugin` | `CommunityMentionsPlugin` (optional, via `hasAtMentions`) |
| `supportRequests` | Support request form | `XHRImageUploadPlugin` | `SyncTextareaPlugin`, `AriaAttributesPlugin`, `AttachInlineImagesPlugin` |

`supportRequests` is only available via `createEditor()` — not `getEditorConfig()` + `<CKEditor>`.

## Do

- Run `yarn changeset` after every code change and include the generated file in your PR
- Keep `src/styles.css` as the **last** import in `src/index.js`
- Use the `translate as t` function from the localization module for all user-visible strings; add new keys to `translations.yml`
- Fetch a CSRF token from the Zendesk API before any image upload (see `XHRImageUploadPlugin.js` and `AUSImageUploadPlugin.js` for the pattern)
- Add new plugins to the per-type `extraPlugins` array in `getEditorConfig()` — not to `Editor.builtinPlugins` unless universally needed
- Test changes via the dev server (`yarn start`) with `public/index.html`

## Don't

- Don't edit `translations/*.json` manually — they are auto-generated by the Zendesk translation system
- Don't hardcode the CKEditor license key — it must come from `process.env.CKEDITOR_LICENSE_KEY_PRODUCTION` or `CKEDITOR_LICENSE_KEY_DEVELOPMENT` (injected at build time by webpack)
- Don't add universally-loaded plugins via `Editor.builtinPlugins` unless they are needed for all editor types
- Don't import `ckeditor5/ckeditor5.css` more than once — it is already imported in `src/index.js`
- Don't use `getEditorConfig()` with `editorType: "supportRequests"` — this combination is unsupported

## Safety & Permissions

Allowed without approval:
- Read/list files
- Run lint (`yarn lint`) and dev server (`yarn start`)
- Run production build (`yarn build`)

Ask before:
- Installing or removing packages
- Deleting files or directories
- Modifying CI/CD workflows
- Pushing to remote branches or publishing to npm

## PR & Commit Guidelines

- Run `yarn changeset` and commit the generated `.changeset/*.md` file alongside your code changes
- Conventional commit prefixes (e.g. `fix:`, `feat:`, `chore:`) are encouraged but not strictly enforced
- Keep PRs focused on a single change
